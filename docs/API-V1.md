# Публичный API v1

Версия 1 — стабильный контракт для внешних клиентов и ИИ-агентов.
Внутренний API редактора (`/api/`) живёт отдельно и может меняться
вместе с интерфейсом; на него ориентироваться нельзя.

## Совместимость

В пределах `/api/v1/` действуют правила:

- существующие поля не удаляются и не переименовываются;
- новые поля могут появляться в ответах — клиент обязан их игнорировать;
- новые необязательные параметры запроса могут появляться;
- смысл поля не меняется;
- ошибка с тем же HTTP-статусом сохраняет свой `code`.

Если нужно сломать совместимость, выпускается `/api/v2/`, а v1
продолжает работать, пока объявлен срок поддержки. Срок фиксируется
в этом документе отдельным коммитом.

Версия ответа всегда видна в заголовке `X-API-Version: 1`.

## Вход

Аутентификация — JWT, как у редактора.

| Шаг | Запрос |
|-----|--------|
| Получить токены | `POST /api/auth/login/` с `{"login": "...", "password": "..."}` |
| Обновить access | `POST /api/auth/refresh/` с `{"refresh": "..."}` |
| Передать токен | `Authorization: Bearer <access>` |

Access живёт 15 минут, refresh — 14 дней с ротацией. Пароль и токены
не должны попадать в URL или логи.

## Формат ответа

Успешный ответ — объект с данными. Списки завёрнуты в `data` и
сопровождаются `meta`:

```json
{
  "data": [{"id": "…", "name": "Ромашка"}],
  "meta": {"total": 1, "limit": 20, "offset": 0}
}
```

Ошибка всегда одной формы:

```json
{
  "error": {
    "code": "not_found",
    "message": "Проект не найден."
  }
}
```

`message` — для человека, `code` — для программы. Коды стабильны:
`invalid_request`, `unauthorized`, `payment_required`, `forbidden`,
`not_found`, `method_not_allowed`, `conflict`, `payload_too_large`,
`unprocessable`, `rate_limited`, `internal_error`.

## Ограничения частоты

Действуют общие лимиты платформы: 1000 запросов в час на
пользователя. При превышении приходит `429` с кодом `rate_limited`.

## Маршруты

### Описание сервиса

`GET /api/v1/` — публичный, без токена. Возвращает версию, способы
входа, список маршрутов и адрес MCP.

### Проекты

`GET /api/v1/projects/?limit=20&offset=0`

Только проекты, где пользователь владелец или участник. `limit` — от
1 до 50. Поля элемента: `id`, `name`, `version`, `role`, `blockCount`,
`pageCount`, `createdAt`, `updatedAt`.

`GET /api/v1/projects/<id>/`

Дополнительно: `brand` (нормализованный брендбук), `tree` главной
страницы и `pages` — список остальных страниц.

Неверный UUID и чужой проект одинаково отвечают `404`: по коду ответа
нельзя перебором узнать, какие проекты существуют.

### Страницы

`GET /api/v1/projects/<id>/pages/`

Полный список, начиная с главной. У главной `slug` — пустая строка,
`isHome` — `true`, `id` — `null`: она хранится в `Project.tree`, а не
в отдельной записи.

`GET /api/v1/projects/<id>/pages/<slug>/`

Страница с деревом блоков. Для главной используйте MCP-инструмент
`get_page` с пустым `slug` или читайте `tree` из проекта.

### Версии

`GET /api/v1/projects/<id>/versions/`

Последние 50 снимков без деревьев: `number`, `label`, `createdAt`,
`blockCount`, `pageCount`. Дерево версии доступно через выгрузку.

### Выгрузка

`GET /api/v1/projects/<id>/export/?version=<n>&pwa=0&baseUrl=<url>`

Возвращает ZIP. Без `version` берётся последняя сохранённая версия;
если снимков нет — `409`.

Требования те же, что у кнопки «Выгрузить»: роль с правом публикации,
тариф не ниже Start, для `pwa=1` — тариф Pro. Заголовки ответа:

- `X-AuraBuilder-Version` — номер версии;
- `X-AuraBuilder-Warnings` — число предупреждений сборки;
- `X-AuraBuilder-PWA` — `1`, если включён сценарий приложения.

Ошибки сборки приходят в общем конверте (`413` при превышении
технического лимита, `422` при невалидном пакете).

## MCP

`POST /api/v1/mcp/` — JSON-RPC 2.0 в режиме Streamable HTTP без SSE
и сессий. Один запрос — один вызов. Аутентификация та же:
`Authorization: Bearer <access>`.

Поддерживаемые версии протокола: `2025-11-25`, `2025-06-18`,
`2025-03-26`, `2024-11-05`. Если клиент просит незнакомую, сервер
отвечает самой новой из списка. Уведомления (`notifications/initialized`
и подобные) получают `202` без тела. Пакетные запросы не
поддерживаются — верните `-32600`.

### Рукопожатие

```json
{"jsonrpc": "2.0", "id": 1, "method": "initialize",
 "params": {"protocolVersion": "2025-06-18",
            "clientInfo": {"name": "agent", "version": "1.0"}}}
```

Ответ содержит `protocolVersion`, `capabilities.tools` и `serverInfo`.
После него клиент присылает уведомление `notifications/initialized`.

### Инструменты

| Инструмент | Аргументы | Что делает |
|------------|-----------|------------|
| `list_projects` | — | Проекты пользователя, до 50 |
| `get_project` | `projectId` | Проект с деревом, брендбуком и страницами |
| `list_pages` | `projectId` | Все страницы, включая главную |
| `get_page` | `projectId`, `slug?` | Страница с деревом; пустой `slug` — главная |
| `list_versions` | `projectId` | Последние 50 снимков |
| `export_summary` | `projectId`, `version?`, `includeManifest?` | Состав сборки и ссылка на архив |

Инструменты только читают. Запись и публикация остаются в редакторе:
у них другая ролевая модель и другие подтверждения.

`export_summary` собирает пакет по-настоящему и поэтому может быть
медленным на большом проекте. Он проверяет те же права и тариф, что
выгрузка. Поле `download` содержит путь к архиву; токен к нему нужно
передать тем же заголовком.

Вызов:

```json
{"jsonrpc": "2.0", "id": 2, "method": "tools/call",
 "params": {"name": "get_project",
            "arguments": {"projectId": "6c4c7a37-…"}}}
```

Результат — `content` с текстом JSON и `structuredContent` с тем же
объектом. Ошибка выполнения инструмента (нет проекта, нет прав) — это
не ошибка RPC: приходит `result.isError: true` с пояснением в
`content`. Ошибки протокола (`-32600`, `-32601`, `-32602`) приходят
в `error`.

## Чего в v1 нет

- создания и изменения проектов, страниц и блоков;
- публикации и деплоя;
- управления участниками, тарифом и интеграциями;
- OAuth и долгоживущих API-ключей: используется JWT.

Эти операции сознательно оставлены внутреннему API. Расширение v1
возможно без слома контракта: новые маршруты и инструменты добавляются
как необязательные.

## Проверка

```powershell
$env:USE_SQLITE='1'
..\.venv\Scripts\python.exe -X utf8 manage.py test api_v1
```

Тесты проверяют доступ, формат ошибок, выгрузку и рукопожатие MCP.

## Клиент

Готовый клиент с типами — `packages/sdk` (`@aurabuilder/sdk`).
`npm run sdk:build` собирает его в `dist`, `npm run sdk:test`
проверяет контракт без Django и без самой платформы. Примеры вызова и
проверки подписи вебхука — в README, раздел «SDK».
