# План развития AuraBuilder

Документ фиксирует порядок работ и то, чего мы сознательно не делаем.
Источник — разбор Postiz, SMMplanner, Amplift и Postmypost: у них
полезны не отдельные экраны, а связка «сделал сайт → проверил → показал
результат → вернулся».

Правило для всех этапов: не трогаем 1С, Telegram и оплату, пока не
закончен текущий этап. Это не «потом», а условие: три интеграции уже
работают, и правка одной ломает две другие.

## Этап 1. Витрина продукта

Цель — чтобы редактор выглядел и вёл себя как продукт, а не как стенд.

- [x] Брендбук проекта: акцент, системный шрифт, подпись внизу страницы,
      UTM-метки для внешних ссылок. Хранится в `Project.brand`, поэтому
      новые поля не требуют миграции.
- [x] Типограф: кавычки, тире, многоточие и неразрывные пробелы при
      экспорте. Консервативные правила, идемпотентность, технические
      поля (адреса, код) не трогаются. Кнопка «Типограф» есть в панели
      свойств.
- [x] MCP/API v1: стабильный контракт `/api/v1/` для внешних клиентов
      и агентов. Чтение проектов, страниц, версий и выгрузка архива;
      MCP по JSON-RPC 2.0 без сессий. Ошибки одним конвертом, правила
      совместимости — `docs/API-V1.md`.
- [x] События Telegram + статус-страница: сборка, публикация и деплой
      оставляют запись в журнале проекта; на экране публикации видна
      лента последних событий. Если к боту привязан чат, событие
      приходит сообщением. Недоступный Telegram не отменяет операцию.
- [x] OG-карточки страниц: PNG 1200×630 рисуется при сборке (Pillow,
      шрифт Inter в репозитории), поэтому превью не зависит ни от
      интернета, ни от системных шрифтов. У главной — `assets/og/index.png`,
      у внутренних — `assets/og/pages/<slug>.png`; при известном домене
      адрес карточки абсолютный.

Что это даёт: сайт на выходе выглядит законченным, а платформа —
предсказуемой. Это дешёвые изменения с заметным эффектом.

## Этап 2. Рабочий процесс

Цель — чтобы сайт можно было вести, а не только собрать один раз.

- [x] Аналитика: просмотры, источники, конверсии форм. Считается на
      раздаче сайта (без скриптов и cookie), заявки хранятся в платформе.
      Отдельный экран «Аналитика»; у статической копии на чужом хостинге
      статистики нет — платформа о ней не знает.
- [x] Отложенная публикация: версия собирается сразу, а текущей
      становится в назначенное время. Задание переживает чистку старых
      версий; отзыв сайта отменяет ожидающие включения. Исполняет
      `publish_scheduled` (cron, systemd или сервис `scheduler`).
- [x] Шаблоны страниц и блоков: снимок удачной страницы или блока
      хранится в проекте (предел — 50). Страница из шаблона создаётся
      обычным API страниц, блок вставляется в палитре «Модули» и получает
      новый идентификатор.
- [x] Ревью-режим: замечания к страницам и блокам, согласование до
      публикации. Комментировать может и Viewer; публикация блокируется,
      пока проект или страница на согласовании или ждут правок. Обход —
      только явным подтверждением того, кто публикует, и он попадает в
      журнал. Комментарии в пакет не выгружаются.
- [x] Академия: короткие текстовые уроки по сборке и ведению сайта,
      разделённые на два курса. Прогресс хранится по пользователю и
      отмечается вручную; содержание живёт в коде рядом с интерфейсом.

Что это даёт: редактор перестаёт быть инструментом одного запуска и
становится рабочим местом.

## Этап 3. Масштаб

Цель — продавать не только сборку, но и инфраструктуру.

- [x] Cloud и self-hosted: один и тот же пакет в двух режимах.
      `DEPLOYMENT_MODE=self-hosted` закрывает регистрацию и отключает
      тарифные проверки; владельца создаёт `create_owner`, лимиты
      остаются техническими. `backup_platform` и `restore_platform`
      снимают и возвращают базу, публикации и медиатеку одним архивом
      с контрольными суммами; ключи шифрования — только явным флагом.
      Установка и приёмка описаны в `docs/SELF-HOSTED.md`.
- [x] Вебхуки: подписки проекта на события публикации и деплоя, подпись
      HMAC, журнал доставок с кодом ответа и повтором неудачных.
      Настраиваются в редакторе; секрет видит только тот, кому доступны
      интеграции.
- [x] SDK: пакет `@aurabuilder/sdk` с типами публичного API v1,
      клиентом (вход, refresh, проекты, страницы, версии, экспорт) и
      проверкой подписи вебхуков через WebCrypto. Без зависимостей,
      работает офлайн и в браузере, и в Node 20+.
- [x] Квоты и кабинет облака: экран «Тариф и квоты» показывает
      занятое место, доступные сценарии и шкалу; кабинет подсказывает
      опубликовать первый сайт и не открывает форму проекта, когда
      лимит уже исчерпан. Смена тарифа действует сразу; оплата — на
      этапе платежей, экран об этом говорит прямо.
- [ ] Кредиты ИИ: понятный расход на генерацию и подсказки.
- [ ] Реестр российского ПО: соответствие требованиям закупок.

## Чего не делаем

Сознательный отказ, чтобы не распылять силы:

- соцсети и OAuth — это другой продукт, а не функция редактора;
- Stories и Reels — форматы, которые не собираются из блоков;
- мобильное приложение — сайт уже адаптивный;
- ИИ-ответы на комментарии — нет самой ленты комментариев;
- нарезка видео — отдельный сервис;
- plug-механики («колесо фортуны», «открой подарок») — одноразовые
  акции, которые быстро устаревают.

## Как проверяем

Каждый пункт считается сделанным, только если:

1. есть тест на поведение, а не на наличие кода;
2. пакет по-прежнему открывается офлайн и без платформы;
3. старые проекты не требуют ручной миграции.
