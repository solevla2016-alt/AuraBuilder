# Протокол рантайма

Рантайм обслуживает опубликованный сайт: корзину, оформление и поиск по
каталогу. Он ставится на сервер заказчика (ТЗ п.16.5) и не входит в
статический архив (ТЗ п.16.4, [ADR-0005](adr/0005-runtime-for-dynamic-modules.md)).

Этот документ — контракт между двумя сторонами: рантаймом и кодом,
который AuraBuilder кладёт в пакет. Стороны обязаны быть согласованы, но
не связаны: рантайм ничего не знает о платформе, а пакет работает и без
рантайма.

## Что делает и чего не делает

* Хранит корзину покупателя между страницами и запросами.
* Принимает заказ и отдаёт его номер для сверки.
* Ищет по каталогу, переданному при развёртывании.
* Хранит всё в одном файле SQLite на сервере заказчика.

Не делает: не принимает платежи, не синхронизируется с 1С, не отправляет
письма. Платёжные данные и персональные данные посетителя не проходят
через платформу — ни при каких настройках (ТЗ п.16.4).

## Конфигурация пакета

Файл `runtime.json` в корне сайта. Пока его нет, три модуля показывают
заглушку и ничего не отправляют.

```json
{
  "version": 1,
  "endpoint": "https://shop.example.ru/api/runtime",
  "siteKey": "..."
}
```

Адрес рантайма указывается без ведущего слэша на конце. Путь
выбирает заказчик, но `/runtime` использовать нельзя: в корне сайта
лежит файл `runtime.json`, и прокси на этот путь перехватил бы его —
сайт перестал бы открываться. Отсюда `/api/runtime` в примере.

| Поле | Назначение |
|------|------------|
| `version` | Версия протокола. Клиент отказывается работать при несовпадении |
| `endpoint` | Базовый адрес рантайма. Только `https` или путь от того же домена |
| `siteKey` | Идентификатор установки. Не секрет: он виден посетителю |

`siteKey` не подпись и не пароль. Он связывает запрос с установкой:
рантайм отвечает только на `siteKey`, который видел при загрузке каталога,
и не отдаёт чужие данные по чужому ключу.

## Каталог

Рантайм читает каталог товаров при старте и по `POST /catalog`:

```json
{
  "siteKey": "...",
  "items": [
    {"id": "t1", "name": "Роза", "price": 1200, "search": "роза цветок"}
  ]
}
```

Поле `search` — текст для поиска. Если его нет, рантайм ищет по `name`.
Порядок и состав каталога определяет заказчик: рантайм не ходит в
источник платформы и не знает о нём.

## Запросы

Все ответы — JSON, поле `ok` сообщает об успехе. Ошибка всегда с
`error` и `message`: клиенту нужно знать, что показать человеку.

| Метод | Путь | Что делает |
|--------|------|-----------|
| `GET` | `/cart` | Текущая корзина и её итог |
| `POST` | `/cart` | Добавить товар, изменить количество или удалить |
| `POST` | `/checkout` | Оформить корзину: заказ и его номер |
| `GET` | `/checkout/{orderId}` | Состояние заказа |
| `GET` | `/search?q=` | Поиск по каталогу |

Заголовок `X-Site-Key` обязателен на всех запросах, кроме `/health`.

### Корзина

```json
POST /cart
{"siteKey": "...", "itemId": "t1", "qty": 2}
```

Ответ:

```json
{"ok": true, "cart": {"items": [{"id": "t1", "name": "Роза", "price": 1200, "qty": 2}],
                      "total": 2400, "count": 2}}
```

`qty` — прибавка к тому, что уже в корзине, а не итоговое количество.
Клиенту известно текущее состояние, поэтому он отправляет разницу: «+1»
означает `qty: 1`, а убрать одну позицию — `qty: -1`. Итоговое количество
означало бы, что два открытых блока корзины на одной странице мешают друг
другу: второй посчитал бы своё и записал поверх первого.

Цена и название берутся из каталога, а не из запроса: прислать свою цену
покупатель может, и сервер обязан её проигнорировать.

Корзина опознаётся по подписанной cookie, а не по заголовку: cookie
ставится при первом обращении и хранит только идентификатор сессии.
Подпись — HMAC с секретом установки, поэтому подделать чужую корзину
похожими символами нельзя.

`qty` ноль или меньше удаляет позицию. Отрицательное количество
отвергается кодом `400` — иначе покупатель «добавил бы» деньги.

### Оформление

```json
POST /checkout
{"siteKey": "...", "name": "...", "phone": "...", "comment": "...", "consent": true}
```

Ответ:

```json
{"ok": true, "order": {"id": "a1b2", "total": 2400, "items": 2, "status": "new"}}
```

Корзина после оформления очищается. `consent` обязателен: без согласия
на обработку персональных данных заказ не принимается (152-ФЗ, ТЗ
п.9.1), и код ответа — `400`.

### Поиск

```json
GET /search?q=роза
{"ok": true, "items": [{"id": "t1", "name": "Роза", "price": 1200}]}
```

Пустая строка `q` возвращает первые позиции каталога: пустой результат
по пустому запросу не объясняет, что поиск вообще работает. Регистр не
учитывается в любом алфавите. Совпадение ищется в любом месте названия и
поля `search`, но вперёд показываются позиции, которые начинаются с
запроса: «розы» окажутся выше «букет роз».

## Коды ответа

| Код | Когда |
|-----|-------|
| `200` | Успех |
| `400` | Неверные данные: нет `siteKey`, неизвестный товар, `qty` меньше нуля, нет согласия |
| `404` | Неизвестный путь или заказ |
| `405` | Метод не поддерживается |
| `429` | Слишком много запросов с одного адреса |
| `500` | Внутренняя ошибка |

## Ограничения

* Запросы принимаются только с того домена, что записан в конфигурации
  установки. Проверяется Origin, а не только cookie.
* Не больше 60 добавлений в корзину и 10 поисков в минуту с одного
  адреса. Молчаливое ограничение выглядело бы как «сайт сломался».
* Тело запроса — не больше 16 КБ.
* Логи не содержат персональных данных: пишется код, адрес и ответ.

## Развёртывание

Рантайм запускается одной командой, база создаётся при первом старте:

```
python3 -m runtime --dir /var/lib/aurabuilder
```

Команда напечатает `siteKey` — его вписывают в `runtime.json` пакета
вместе с адресом. Дальше корзина, оформление и поиск начинают работать
сами.

За обратным прокси (nginx) или на выделенном порту. Требований к
PostgreSQL и внешним сервисам нет: это сделано для shared-хостингов
Timeweb, Beget, Selectel и Reg.ru (ТЗ п.16.5).

Пример правила nginx:

```
location /api/runtime/ {
    proxy_pass http://127.0.0.1:8088/;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
}
```

Путь `/runtime` использовать нельзя: в корне сайта лежит файл
`runtime.json`, и прокси на этот путь перехватит его — сайт перестанет
открываться.

### Каталог

Каталог берётся из данных пакета: рантайм загружает
`assets/data/data.json` с того же сервера, и идентификаторы товаров
(`t1`, `t2`…) совпадают с теми, что ставит кнопка «В корзину». Пока
каталог не загружен, товар добавить нельзя: сервер отвечает
`unknown_item`, и клиент показывает это сообщение.

Загрузить свой каталог можно вручную — `POST /catalog` (см. выше).
Ручная загрузка перезаписывает автоматическую: так заказчик может
держать цены в 1С и обновлять их, не пересобирая сайт.

### Если что-то не работает

| Симптом | Причина |
|---------|---------|
| Заглушка «нужен рантайм» не исчезает | В `runtime.json` пуст `endpoint` или `siteKey` |
| В консоли `Версия протокола не совпадает` | Пакет собран под другую версию, чем сервер |
| «Товар не найден в каталоге» | Каталог не загружен или собран без данных |
| 403 на запросы | Origin сайта не указан в `allowedOrigins` на сервере |
| 429 | Сработал лимит: много добавлений или поисков с одного адреса |

## Совместимость

Поле `version` в `runtime.json` и ответ `/health` — `runtimeVersion`.
Клиент отказывается подключаться при несовпадении и показывает заглушку:
лучше показать «модуль не подключён», чем слать запросы в несовместимый
формат и получать ошибки на каждом нажатии.

Версия 1 — первая. Изменения, ломающие совместимость, получают новый
номер, а не заменяют прежний: старые пакеты у заказчиков останутся
работать.
