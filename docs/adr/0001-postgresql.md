# ADR-0001. PostgreSQL вместо MySQL

- **Статус:** принято
- **Дата:** 2026-09-30
- **Связано с:** ТЗ п.0.2, `docs/TZ-GAPS.md` п.1.2

## Контекст

ТЗ предписывает PostgreSQL для хранения данных. На этапе 0 выяснилось,
что Python-драйвер `psycopg` распространяется под LGPL-3.0-only, а
собственное правило лицензионной чистоты (ТЗ п.7.1.6) запрещает
copyleft в зависимостях. Драйверы `psycopg2` под тот же запрет не
попадают — они под LGPL-2.1, то есть слабее, — но оба они Cython,
собираются из исходников и тянут за собой libpq.

Django с PostgreSQL работает через `psycopg`, а для SQLite встроенного
достаточно: стенду браузерных сценариев внешняя СУБД не нужна.

## Решение

Основное хранилище — PostgreSQL 18 (контейнер `db` в compose).
Python-драйвер — `psycopg[binary]`, версия закреплена в
`apps/requirements.txt`.

## Последствия

- LGPL-3.0-only в зависимостях остаётся, и это зафиксировано как
  исключение из п.7.1.6 в `docs/TZ-GAPS.md`: LGPL обязывает
  предлагать исходники psycopg, но не распространяет условия на
  AuraBuilder. Замена на MySQL не рассматривалась: это смена СУБД
  из-за лицензии драйвера, то есть из-за проблемы, которой нет.
- `pg8000` оставлен как запасной вариант на случай, если лицензия
  psycopg станет неприемлемой для заказчика. Он чистый Python,
  работает через pg8000-native протокол, но медленнее и требует
  SQL-запросов вместо параметров psycopg.
- Локальный стенд и CI используют PostgreSQL, поэтому расхождения
  между СУБД не маскируются.

## Отвергнутые варианты

| Вариант | Почему не подходит |
|---------|--------------------|
| MySQL | Требует MariaDB в compose и теряет `jsonb` и `RETURNING`; выигрыш не окупает смену СУБД |
| Только SQLite | Не проверяет то, что будет в бою; расхождения всплывают на приёмке |
| `psycopg2` | Cython и сборка из исходников; LGPL-2.1, но практически сложнее без выигрыша |
