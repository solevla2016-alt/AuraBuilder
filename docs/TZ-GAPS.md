## 2. Открытые вопросы — блокирующие

### 2.1. Сегмент Г: госзаказчики и реестр Минпромторга — **BLOCKER**

ТЗ (п.2, Сегмент Г) обещает «использование только отечественного ПО с реестром
Минцифры». Django, React, PostgreSQL, Valkey в реестре **отсутствуют**.

**Варианты:**
- **А.** Оставить стек, вывести сегмент Г из обязательных требований (рекомендую).
- **Б.** Частичная замена: 1С:Элемент / ClickHouse — отдельный проект на 6+ месяцев.
- **В.** Enterprise-поставка с «зеркальным» стеком и регистрацией ПО в Роспатенте (п.13.3) —
  это не то же самое, что реестр ПО.

> **Нужно решение заказчика.** От ответа зависит, закладывать ли в смету 6–12 месяцев.

### 2.2. Тестовый стенд 1С — **BLOCKER для этапа 7**

Требуется лицензия 1С:Предприятие 8.3 для разработчиков + база 1С:УТ с 1000+
позиций для проверки KPI «синхронизация ≤ 5 минут». В бюджете (п.14.1–14.3) не
заложено. Без стенда этап 7 (1.5 месяца) невыполним.

**Варианты:** аренда стенда у интегратора (30–80 тыс. ₽/мес) | покупка лицензии
1С:УТ (~25–40 тыс. ₽) | силами заказчика.

### 2.3. Модель конкурентного редактирования

RBAC (п.11.1) предполагает команду над проектом, но модель одновременной работы
не описана. Варианты: блокировка документа | CRDT | Optimistic concurrency
с merge.

**Рекомендация:** optimistic concurrency по версиям документа (в ТЗ уже введены
`DocumentVersion`, п.3.2) + предупреждение о конфликте.

### 2.4. Row-level security

При командной работе и нескольких проектах нет описания изоляции данных на
уровне записей. Указан как ADR в п.3.2, требует подтверждения.

## 3. Открытые вопросы — влияют на смету

### 3.5. Интеграции без контрактов

В п.7.4 перечислено 25+ сервисов (ЮKassa, СДЭК, Битрикс24, Wildberries, Ozon,
Яндекс.Маркет, SMS.ru, VK ID, Max, VK, Telegram…). Для каждого отсутствуют:
объём (создание/изменение/удаление), тарифная модель, SLA, песочница, сроки.

**Оценка:** каждая интеграция — отдельная задача на 3–10 дней. Полный список —
это 2–4 месяца работы, которых нет в графике этапов 1–10.

> **Нужно:** приоритизировать список. Предлагаю на MVP: ЮKassa + СДЭК + VK ID.

### 3.6. Бюджет не покрывает заявленные требования

| Пентест (п.7.7.3) | Нет |

### 3.7. Сроки: 187-ФЗ и КИИ

IP Safety. Требования 187-ФЗ (категорирование, аттестация, сертифицированные СЗИ,
уведомление ГосСОПКА) реалистично **не укладываются** в этот срок.

## 4. Открытые вопросы — продуктовые

### 4.8. Каталог модулей

п.3.3 и п.15.2 вводят термин «Модули / Секции», но перечень отсутствует. Без него
невозможно оценить этап 3 (3 месяца на редактор).

### 4.9. Дизайн-токены неполны

Определены 10 цветов (п.5.1). Отсутствуют: шкала отступов, типографическая
шкала, радиусы, motion-спецификация, z-index-слои, темизация.

### 4.10. Доступность (WCAG)

Требований нет. Для сегмента Г (госзаказчики) может быть обязательной. Особенно:
клавиатурная навигация drag-and-drop, скринридеры, контраст песочной палитры
(#D4B896 на #F5EFE0 — **контраст 1.7:1, ниже порога WCAG AA 4.5:1**).

> Это реальный дефект палитры: акцентный текст на песочном фоне нечитаем.
> Нужны затемнённые варианты акцента для текста.

### 4.11. Лимиты системы

Не заданы: макс. модулей на страницу, макс. нод в графе логики, макс. записей
в узле данных, размер проекта. Частично закрыто тарифами (п.17.1), но нужны
и технические потолки.

### 4.12. Поведение при истечении подписки

Сайт перестаёт работать? Данные хранятся? В п.17.5 внесено «30 дней + уведомление
за 14 дней», требует подтверждения коммерческой политики.

### 4.13. Что происходит с бэкендом в сценарии 3

п.16.5: «сайт работает на серверах клиента, но управляется через AuraBuilder».
Код редактора должен где-то работать — не описано. Требует отдельной архитектуры.

### 4.14. API-ключи без бэкенда

п.17.3 отдаёт «API-ключи для доступа к данным», но бэкенд не отдаётся.
Противоречие ТЗ. Требуется формулировка: ключи работают только пока сайт
обслуживается платформой.

### 4.15. ПЭП / УКЭП (п.9.6)

Интеграция (КриптоПро?) не описана, лицензии не учтены, этап не выделен.

### 4.16. Автомодерация и blacklist РКН (п.9.5)

Не указан источник данных blacklist, периодичность обновления, ответственный.
Без feed РКН это нереализуемо.
