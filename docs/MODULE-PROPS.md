# Схемы свойств модулей

Назначение: что именно настраивается у каждого модуля в контекстной панели.

Список модулей живёт в `docs/MODULE-CATALOG.md`, а этот документ описывает
настройки. Оба идут в одну генерацию: правка здесь требует
`python tools/props_to_registry.py` и `npm run registry:build`.

## Статус: девять модулей

Схемы описаны для девяти модулей MVP: `section.hero`, `text.heading`,
`text.paragraph`, `section.split`, `section.cards`, `section.cta`,
`action.button`, `action.link`, `data.collection`, `data.single`,
`data.field`, `data.list`, `data.search`, `data.pagination`.
Остальные пока используют общий набор полей.

Порядок такой: сначала проверяется форма схемы на реальных данных,
потом она разворачивается на модули данных, потому что у них своя
специфика — привязка к источнику. Разворачивать сразу все 65
означало бы рисковать получить 65 описаний неправильной формы.

## Свойства модулей данных

Шесть модулей `data.*` входят в MVP (ТЗ п.12) и привязываются к узлу
данных проекта. Ключевое свойство у них одно и то же — `source`,
идентификатор источника; оно выбирается из списка в панели свойств,
поэтому в схеме оно описано как текст со значением по умолчанию `—`.

Значение `—` означает «источник не выбран». Пока источник не выбран,
модуль рисует пустой каркас: молча подставлять первый источник значило
бы привязать блок к чужим данным без спроса.

## Формат описания

```text
### <id модуля>
| Свойство | Тип | Обяз. | По умолчанию | Ограничения | Описание |
```

Типы: `text`, `textarea`, `number`, `select`, `boolean`, `color`.

Ограничения для `number` — `min`, `max`, `step` через запятую.
Ограничения для `select` — варианты через запятую.

Обязательные свойства дублировать в данные блока не нужно: при вставке
модуля подставляется значение по умолчанию. В дереве хранится только то,
что пользователь изменил, — иначе каждый блок раздувался бы одинаковыми
значениями.
