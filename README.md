# AuraBuilder

Платформа для создания веб-приложений (No-Code / Low-Code) с визуальным
редактором, нодо-ориентированным конструктором логики и визуальной базой данных.

## Статус

Проект находится на стадии **проектирования**. Кода платформы ещё нет.
В репозитории лежат:

| Путь | Описание |
|------|----------|
| `AUIRA ТЗ.docx` | Техническое задание, версия 4.1 (исправленная по результатам аудита) |
| `docs/TZ-GAPS.md` | Пробелы ТЗ, принятые решения, открытые вопросы |
| `docs/MODULE-CATALOG.md` | Каталог модулей редактора: 65 модулей в 5 категориях |
| `tools/` | Служебные скрипты работы с ТЗ (см. ниже) |

## Техническое задание

Актуальная редакция — **v4.1**. В шапке документа находится таблица всех
внесённых изменений относительно v4.0 (23 правки).

Ключевые изменения v4.1:

- **Email-сервис:** Resend исключён (резидент США, трансграничная передача ПДн).
  Основной провайдер — Mailganer (в реестре российского ПО № 20310),
  резерв — собственный SMTP (Maddy + Rspamd). Добавлен слой абстракции
  `EmailProvider` и автоматический фейловер по circuit breaker.
- **Хранение кода:** GitHub (решение заказчика, отступление от п.15.3 п.6).
  В Enterprise-поставке — self-hosted Forgejo.
- **Заменены зависимости, нарушавшие собственные правила ТЗ:**
  Redis → Valkey (RSALv2/SSPLv1), RabbitMQ исключён (MPL-2.0),
  Dovecot → Maddy (GPLv2), ClamAV исключён (GPLv2),
  SonarQube/FOSSA → Trivy + Grype + Syft.
- **Заполнены пустые разделы:** 3.2 (архитектура), 7.5.2–7.5.4 (1С),
  7.6.3 (шаблоны писем), 16.2 (Export Engine), 16.4 (структура архива),
  17.5 (юридическая защита).
- **Добавлен этап 0** — каркас платформы и CI/CD.
- **Тарифы приведены к единой шкале** (устранено противоречие п.16.3–16.7 и п.17.1).
- **Добавлен раздел 5.1.1** — доступность палитры: измеренный контраст
  акцентных цветов не проходит WCAG (1.65:1), введены токены `accent-text`.
- **Добавлен раздел 4.5** — каталог модулей редактора (65 модулей, 5 категорий).
- **Сегмент Г исключён** из объёма MVP: стек платформы отсутствует в реестре
  российского ПО. Требования 152-ФЗ и локализация сохраняются.
- **1С: закупка лицензии** 1С:Предприятие 8.3 подтверждена как обязательная;
  таблица закупок и оценки — в п.7.5.3.
- **187-ФЗ (КИИ)**: платформа не аттестуется, обязанности перенесены на оператора.

## Работа с ТЗ

ТЗ хранится в формате `.docx` и редактируется скриптами, чтобы сохранить
форматирование, списки и таблицы.

```bash
# карта абзацев с индексами и типами (для точечных правок)
python tools/tzedit.py map "AUIRA ТЗ.docx"

# найти абзацы по подстроке
python tools/tzedit.py find "AUIRA ТЗ.docx" "7.5"

# заменить текст во всех абзацах, где он встречается
python tools/tzedit.py replace "AUIRA ТЗ.docx" "старое" "новое"

# заменить диапазон абзацев [start,end) содержимым спецификации
python tools/tzedit.py set "AUIRA ТЗ.docx" 276 303 tools/edits/76_email.txt

# заменить узел (обычно таблицу) по индексу
python tools/tzedit.py settable "AUIRA ТЗ.docx" 833 tools/edits/tariffs.txt
```

Спецификации правок лежат в `tools/edits/`. Формат строк:

| Директива | Значение |
|-----------|----------|
| `B\|текст` | жирный абзац |
| `P\|текст` | обычный абзац |
| `I\|текст` | курсив |
| `C\|текст` | строка кода (моноширинный, фон `#F5EFE0`) |
| `CB` | пустая строка кода |
| `BL\|ilvl\|текст` | маркированный список (новый `numId` на блок) |
| `DL\|ilvl\|текст` | нумерованный список |
| `NEW` | начать новый блок списка (сбросить нумерацию) |
| `TABLE` … `ENDTABLE` | таблица; строки `ROW\|a \|\|\| b` |

## Проверка целостности

```bash
python tools/verify.py "AUIRA ТЗ.docx"      # XML, numId, таблицы, остаточные термины
python tools/contrast.py                    # контраст палитры по WCAG
python tools/show_table.py "AUIRA ТЗ.docx" "Тариф"   # содержимое таблицы
```

## Лицензионная чистота

ТЗ требует пермиссивных лицензий во всех зависимостях (п.7.1.6). Лицензионный
gate в CI — первая задача этапа 0: пайплайн падает при появлении зависимости
с лицензией вне списка (MIT, Apache 2.0, BSD).
