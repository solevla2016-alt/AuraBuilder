B|🆕 7.6. EMAIL-СЕРВИС (РОССИЙСКИЕ ПРОВАЙДЕРЫ)
B|7.6.1. Назначение email-сервиса:
BL|0|Восстановление пароля (reset password)
BL|0|Подтверждение email при регистрации
BL|0|Уведомления о действиях в системе
BL|0|Транзакционные email (чеки, счета, уведомления)
B|7.6.2. Реализация:
P|Проектный слой абстракции (EmailProvider) скрывает конкретного провайдера от прикладного кода. Смена провайдера выполняется конфигурацией, без изменения кода.
C|
C|class EmailProvider(Protocol):
C|    async def send(self, msg: EmailMessage) -> DeliveryReceipt: ...
C|
C|# Провайдеры регистрируются по ключу:
C|#   {"mailganer": MailganerProvider, "smtp": SMTPProvider, "selfhosted": ...}
C|
C|# Переключение: конфиг + запись в БД, горячий reload без деплоя
C|EMAIL_PROVIDER = os.environ["EMAIL_PROVIDER"]  # mailganer | smtp
C|
C|provider = resolve_provider(settings.EMAIL_PROVIDER)
C|await provider.send(msg)
B|Автоматический фейловер (п.7.6.4) реализуется на уровне провайдера:
C|
C|class FailoverEmailProvider(EmailProvider):
C|    async def send(self, msg):
C|        for p in self.chain:  # [mailganer, selfhosted_smtp]
C|            try:
C|                return await p.send(msg)
C|            except ProviderError as e:
C|                self.log.warning("provider %s failed: %s", p.name, e)
C|                self.circuit_breaker.record_failure(p.name)
C|        raise AllProvidersFailed(msg)
B|7.6.3. Шаблоны email:
BL|0|Восстановление пароля (reset_password) — срок действия ссылки 60 минут, одноразовая
BL|0|Подтверждение email (verify_email) — срок действия 24 часа
BL|0|Уведомление о входе с нового устройства (new_login_alert)
BL|0|Уведомление о смене email/пароля (security_change)
BL|0|Заказ создан (order_created)
BL|0|Чек оплаты (payment_receipt)
BL|0|Уведомление 1С об ошибке синхронизации (sync_error)
P|Требования к шаблонам: HTML-версия обязательна, plain-text fallback; все шаблоны вынесены в файлы локализации; поддержка подстановки переменных проекта; в письмах не допускается передача ПДн за пределы РФ.
B|7.6.4. Провайдеры и стратегия отказоустойчивости:
P|Основной провайдер — Mailganer (участник реестра российского ПО № 20310, серверы в РФ, заявленное соответствие 152-ФЗ, API, SMTP-транспорт, поддержка on-premise и выделенных IP).
P|Резервный провайдер — собственный SMTP на инфраструктуре платформы: Maddy (MIT) + Rspamd (Apache 2.0), либо Mailu (MIT) как готовая обёртка.
NEW
BL|0|Mailganer — основной провайдер (в реестре российского ПО, 152-ФЗ, транзакционные и триггерные письма)
BL|0|Физический SMTP (Maddy + Rspamd) — резерв, полный контроль, Zero Foreign Dependency
BL|0|Автоматическое переключение по circuit breaker: 3 ошибки подряд → переключение, восстановление по health-check
BL|0|Минимизация данных: передавать только email-адрес и необходимые технические поля, без иных ПДн
BL|0|Локальное логирование всех отправленных писем (тело, статус, provider_id) в БД платформы
BL|0|Обязательные заголовки: SPF, DKIM, DMARC для собственного домена; выделенный IP с прогревом репутации
NEW
B|⚠️ Исключённые варианты:
BL|0|Resend (США) — исключён: трансграничная передача ПДн, санкционный риск блокировки, зависимость от иностранной инфраструктуры
BL|0|Dovecot (GPLv2) — исключён: запрещён п.7.1.6; заменён на Maddy (MIT)
BL|0|SMTP.ru / Yandex 360 / Selectel Email — остаются как допустимые альтернативы на этапе выбора провайдера, но не входят в базовую конфигурацию
B|Результат: все транзакционные письма платформы обрабатываются резидентами РФ, трансграничная передача ПДн исключена, что обеспечивает выполнение п.9.1 и KPI «100% независимость от иностранных API в ядре продукта».
