B|7.5.2. Методы подключения:
B|A. REST API (рекомендуется для 1С:Предприятие 8.3):
P|Пример клиента HTTP-сервиса 1С. Базовый URL указывается в настройках проекта (п.7.5.5), учётные данные хранятся в шифрованном виде.
C|
C|class OneCClient:
C|    BASE: str          # https://company.ru/hs/aurabuilder/
C|    PREFIX: str        # префикс обмена (мультитенантность)
C|
C|    def _auth(self):
C|        # логин/пароль шифруются AES-256 при сохранении, в памяти — plaintext
C|        return HTTPBasicAuth(self.login, self.password)
C|
C|    def get_products(self, since: str, page: int = 1) -> dict:
C|        """Инкрементальная выборка. since — метка последней синхронизации (ISO 8601)."""
C|        r = httpx.get(
C|            f"{self.BASE}{self.PREFIX}/Catalog/Products",
C|            params={"since": since, "page": page, "size": 500},
C|            auth=self._auth(), timeout=30.0,
C|        )
C|        r.raise_for_status()
C|        return r.json()          # {"items": [...], "total": N, "next_page": int|None}
C|
C|    def push_order(self, order: dict) -> str:
C|        """Возвращает GUID документа, созданного в 1С."""
C|        r = httpx.post(
C|            f"{self.BASE}{self.PREFIX}/Document/CustomerOrder",
C|            json=order, auth=self._auth(), timeout=30.0,
C|        )
C|        r.raise_for_status()
C|        return r.json()["ref"]
B|Протокол обмена:
BL|0|Формат: JSON (по умолчанию) либо XML для конфигураций без поддержки JSON
BL|0|Аутентификация: HTTP Basic; для чувствительных контуров — клиентский сертификат (mTLS)
BL|0|Идемпотентность: каждый объект передаётся с внешним ключом (GUID 1С); повторная отправка того же GUID не создаёт дубль
BL|0|Кодировка: UTF-8; даты — ISO 8601 с часовым поясом (Europe/Moscow)
BL|0|Постраничность: сервер 1С обязан поддерживать параметры page/size; при отсутствии — пагинация на стороне платформы
B|B. SOAP/COM (для старых версий 1С):
BL|0|Поддержка через библиотеку zeep (Python SOAP-клиент, MIT)
BL|0|Альтернатива: прямое подключение через OData

B|Правила маппинга:
BL|0|Сопоставление записей выполняется по внешнему ключу: GUID 1С ↔ поле external_id узла данных
BL|0|Записи без совпадения создаются в направлении 1С → AB; в направлении AB → 1С требуется предварительное сопоставление по ИНН/артикулу
BL|0|Преобразование типов: Цена → Decimal(15,2); Дата → DateTime; Перечисление → строковый код с таблицей соответствий
BL|0|Поля, отсутствующие в 1С, не заполняются и помечаются в логе обмена как пропущенные
BL|0|Удаление в 1С не удаляет запись в платформе — запись переводится в статус «Архив» (мягкое удаление)
B|Требования к тестовому стенду (этап 7):
BL|0|Наличие лицензии 1С:Предприятие для разработчиков — затраты и сроки в бюджет не заложены, требуется согласование
BL|0|Эталонная база 1С:Управление Торговлей с 1000+ позиций для проверки KPI (синхронизация ≤ 5 минут)
BL|0|Набор тестовых сценариев: полная выгрузка, инкрементальная, обработка ошибок, конфликт приоритетов, повторная отправка
B|7.5.4. Расписание синхронизации:
C|
C|# Celery beat: периодический запуск задачи синхронизации
C|app.conf.beat_schedule = {
C|    "sync-1c-products": {
C|        "task": "integrations.onec.sync_products",
C|        "schedule": crontab(minute="*/15"),   # каждые 15 минут
C|    },
C|    "sync-1c-orders": {
C|        "task": "integrations.onec.push_orders",
C|        "schedule": crontab(minute="*/5"),    # заказы — чаще
C|    },
C|    "sync-1c-full": {
C|        "task": "integrations.onec.full_sync",
C|        "schedule": crontab(hour=3, minute=0), # полная сверка — ночью
C|    },
C|}
C|
C|@app.task(bind=True, max_retries=5, autoretry_for=(TimeoutError,))
C|def sync_products(self, integration_id: int):
C|    integ = Integration.objects.get(pk=integration_id)
C|    since = integ.last_sync_at.isoformat()   # инкрементально с последней метки
C|    for page in client.pages(since=since):
C|        apply_page(integ.project, page)       # маппинг полей по п.7.5.3
C|    integ.last_sync_at = timezone.now()
C|    integ.save(update_fields=["last_sync_at"])
