B|3.2. Архитектура платформы:
P|Система разбита на четыре контура. Взаимодействия — только через API и очереди, прямых обращений к БД соседних контуров нет.
NEW
DL|0|Контур управления (Control Plane) — Django 5 + DRF. Управляет проектами, пользователями, правами, визуальной CMS, интеграциями, тарифами и аудитом. PostgreSQL, схема public.
DL|0|Контур рантайма (Runtime Plane) — обслуживает запросы опубликованных сайтов: рендеринг, приём форм, исполнение логики. Изолирован от редактора, масштабируется горизонтально отдельно.
DL|0|Контур фоновых задач (Async Plane) — Celery + Valkey Streams. Экспорт, синхронизация с 1С, отправка писем, обработка изображений, генерация превью.
DL|0|Контур редактора (Editor) — React 18 + TypeScript + Konva.js. Клиентское приложение; состояние проекта хранится в Control Plane, тяжёлые операции уходят в Async.
NEW
B|Ключевые потоки данных:
BL|0|Редактирование: Editor → PATCH /api/v1/projects/{id}/document → Control Plane → сохранение версии документа (append-only) + рассылка события в WebSocket
BL|0|Публикация: Editor → POST /api/v1/projects/{id}/publish → Celery-задача → сборка бандла → выкладка в Object Storage → инвалидация кэша CDN
BL|0|Запрос к сайту: браузер → CDN (G-Core / Yandex) → кэш Runtime → при промахе обращение к данным проекта
BL|0|Событие логики: действие на сайте → Runtime → вычисление графа нод (Logic Graph) → действие (запись в БД / вызов интеграции / отправка письма)
BL|0|Синхронизация 1С: Celery beat → HTTP-сервис 1С → маппинг полей → применение изменений по приоритету (п.7.5.6) → запись в лог обмена
NEW
B|Модель данных (верхний уровень):
TABLE
ROW|Сущность ||| Назначение ||| Ключевые связи
ROW|User ||| Аккаунт, согласие на обработку ПДн ||| 1:N Project, 1:N Membership
ROW|Project ||| Проект: документ, настройки, статус публикации ||| 1:N Page, 1:N DataNode, 1:N LogicGraph
ROW|DocumentVersion ||| Неизменяемая версия документа проекта (undo/redo, аудит) ||| N:1 Project
ROW|Page ||| Страница: дерево модулей, ЧПУ, SEO ||| N:1 Project
ROW|DataNode ||| Узел данных (замена Collections) ||| N:1 Project, N:1 Field
ROW|LogicGraph ||| Граф бизнес-логики из нод и связей ||| N:1 Project, 1:N Node
ROW|Integration ||| Подключение внешнего сервиса (1С, ЮKassa, CRM) ||| N:1 Project; секреты — в шифрованном виде
ROW|Deployment ||| Публикация: окружение, домен, статус, версия бандла ||| N:1 Project
ENDTABLE

B|Принятые архитектурные решения (ADR):
BL|0|Монорепозиторий: backend/, frontend/, export-engine/, integrations/, deploy/, docs/
BL|0|Хранение состояния проекта — append-only версии документа; текущая версия указывает на последнюю запись. Это даёт undo/redo, аудит и корректный экспорт без конфликтов записи
BL|0|Версионирование API префиксом /api/v1/; обратная совместимость в пределах минорной версии
BL|0|Аутентификация редактора — JWT (15 мин) + refresh с ротацией; публичные сайты используют отдельный механизм (Edge-токен) для изменяемых запросов
BL|0|Изоляция проектов на уровне строк (RLS в PostgreSQL) — обязательное требование при командной работе над одним проектом
